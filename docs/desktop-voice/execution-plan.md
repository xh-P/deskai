## 目录约定（部分已实现）

```text
apps/desktop/                 Electron 主进程、preload、React UI
packages/voice-core/           纯逻辑：轮次状态、协议解析、分句、播放账本
packages/dsh-adapter/          Gateway 认证、speech、session、事件去重
services/tts/                  v2 worker、控制协议、声音注册表
config/voice/                  应用默认配置及 dsh 启动 patch
config/personas/               轻量有希、普通助手、用户扩展
tests/voice/                   回放 fixture、并发/取消/重连测试
outputs/desktop-validation/    测试证据与汇总，不保存凭据
docs/desktop-voice/            本交接方案与后续变更记录
```

可根据打包工具调整组织，不允许把应用直接写进 node_modules。GPU服务一次只允许一个执行者，测试也串行占用 GPU；纯逻辑和 UI 工作可并行。

## M0：接口与风险验证，先于大规模 UI

工作：

1. 读取本地实际类型与组合，建立专用 profile/preset；确认有效工具表为空、coding persona 被正确替换、现有登录可受支持地复用。保留用户旧配置。
2. 验证 speech prepare/catalog/transcribe，三种语言各一段；确认资源目录、CPU运行、取消与 idleTimeout 行为，测冷/热延迟。
3. 用最小 dsh 会话验证 assistant text/reasoning chunk 区分、prompt 接受回执、cancel、reconnect baseline、最终 message 去重；固定所用协议版本。
   同时记录生成前、流式中、提交后取消时 dsh 实际保留的历史；确认控制头会如何进入下一轮及压缩，验证 deliveryState 或历史投影扩展点。
4. 对同一提供方验证 SPEAK/WAIT/SILENT 控制头是否能稳定输出并流式消费；记录解析失败次数和 tokens。若不能稳定，先改适配/模板而非绕过协议照读所有文本。
5. 实际确认 Electron 音频链路、AEC 请求和所用设备支持；选定前端 VAD 包/模型版本并检查官方许可。选择 TTS 的 IPC 方案，完成一次合成和取消握手。

完成门禁：有实际契约样本（已脱敏）与测试报告；能证明不是以关闭麦克风来实现“防回声”。M0 的临时界面可以简陋，不需要完整产品 UI。

## M1：自动采集、AEC 和轮次核心

工作：

- 实现会话开启/结束、麦克风权限、AudioWorklet、真实重采样、环形缓冲、VAD、动态尾静音、长录音有界切片。
- 输入、输出双状态机；ASR串行有界队列，旧任务隔离，新输入合并；本地过滤和控制语规则。
- 实现播放期间仍采集、候选插话暂停/减音、确认/误触发恢复。保留纯文本模拟和录音 fixture，便于无硬件回归。

完成门禁：固定 WAV 回放的边界/合并测试通过；开口首字没有因起音裁剪丢失；输入在播放时可继续；“嗯”的两个不同上下文不走同一硬编码过滤；未准备时 UI 不显示已就绪。

## M2：选择性回应与人格接入

工作：

- 实现单请求决策头解析、SPEAK正文流、WAIT/SILENT静音；分块边界、长度上限、错误隔离。
- 实现 turn-policy 中明确规则、pending状态、submittedThroughUtteranceId、空闲无主动调用。
- 按层构建有效 prompt；轻量有希与普通助手卡；语言与声音独立；记录 promptVersion/personaRevision。
- 建立用户显示历史和播放账本，模型下一轮得知被打断事实。关闭 follow 不能代替 session.cancel。
  测试尚未播出的内容不得被当成用户已知；期待回答的状态必须等问题实际播到后才生效，WAIT/SILENT不能清空旧问题。标记法不可靠时实现上下文投影再验收。

完成门禁：每个协议边界有确定性单元测试；至少 30 个中/日/英人工标注的语义案例（包括策略文档全部最低案例）。报告每例预期/实际，不仅报总准确率。明确请求/停止等硬案例不得失败；歧义案例差异需人工审阅再调整策略。

## M3：逐句 TTS、播放与换声

工作：

- v2 常驻、FP16、CUDA Graph、单请求互斥；默认常态有希参考。
- 正文安全切句、有限前瞻、PCM 编号、AudioWorklet播放、背压、实际采样率处理。
- generation/attempt 去重与取消；迟到 PCM 丢弃；暂停恢复不复读；所有worker错误有可恢复状态。
- 导入10角色映射并核对资源，切换成套权重/参考、加载失败回滚、预热状态。

完成门禁：同一输入文本无重复/漏播；多次中断后没有旧声音复活；十角色逐个加载并生成短音频；32/48 kHz 输入均不变速；换声期间不混合旧GPT和新SoVITS。

M1/M2/M3 单元工作可交叉推进，整体自动对话必须在进入 M4 前贯通。不得把仅“按键成功”当作自动语音已完成。

## M5：端到端验收与交付

实测机：RTX 4060 Laptop 8 GB、Ryzen 9 7945HX，记录实际设备/电源/后台负载。不占用麦克风却声称物理设备通过是无效验收。

### 行为和可靠性

- 中/日/英各至少 10 轮自然会话，验证短回答、停顿、修改、跨语言、安静和恢复。
- 耳机与至少一种物理扬声器：各 20 次 AI 自播无用户输入，目标 0 次新模型回复；各 10 次真实插话，目标至少 9 次正确取得话权。属于该环境验收，不宣称任意房间都满足。
- 插话包括：键盘/咳嗽/呼吸假起音、纯附和、真正问题、停止、用户复述AI；无关背景音不应形成回复环。
- 100 次随机取消/换声/重连时序回放：0 次旧 generation 音频播放、0 次控制标记朗读、0 次最终事件重复播放。
- 30 分钟对话和 20 次角色切换：模型缓存预热后不持续单调增长；有显存/RSS曲线和前后数据。无OOM、无无界队列、退出无本应用孤儿进程。
- 沉默10分钟或重复WAIT：0次定时主动模型调用；20条明确本地过滤样本：0次LLM调用。一般需要模型判断的有效输入至多1次决策/回复请求；提供方重试、上下文压缩另列，不能藏入平均值。

### 性能指标

统一采集单调时钟时间戳：userSpeechStart、userSpeechEnd、endpoint、asrStart/end、llmRequest、decisionHeader、firstSpeakableSentence、ttsStart/firstPCM、firstPlayback、interruptCandidate/confirmed、playbackStopped。

- 首声端到端 = firstPlayback - userSpeechEnd。WAIT/SILENT 不计入首声延迟，另计决策耗时及占比。
- 打断同时报告开口→停播、确认事件→停播；后者初始目标 p95 ≤150 ms，前者初始目标 p95 ≤500 ms。
- 本地ASR对典型2–8秒语音初始目标热启动 p95 ≤800 ms；TTS对正常短句 firstPCM 初始目标 p95 ≤1秒；这两个是待验证目标，不是已有测量。
- 首声 p50/p95 对 ≥30 个 SPEAK 轮次测量，报告网络/DeepSeek首句贡献。首版优化目标中位数约2秒量级，不作为当前机器已达成的承诺；不得把只测TTS替代端到端。
- 记录每有效轮次输入/输出tokens、请求数；本地噪声和本地控制语不触发额外模型账单。

### 必须交付

1. 可运行桌面入口、环境说明和停止/恢复说明。
2. 本地资源清单，含默认常态v2、角色参考、配置和版本；不包含凭据。
3. 测试报告、未通过项、使用设备和可复现命令；不能用“基本可用”掩盖自然插话或选择性回应失败。
4. 用户可试听和实际对话的演示；说明哪些经过自动检查、哪些经过真人听校。
5. 更新本目录状态：逐项完成/未完成/阻塞，不把原始计划全部标完成。

## 允许的降级与不允许的替代

允许：网络故障保留文字转写、TTS故障显示文字；特定外放设备AEC未通过时明确提示耳机；模型格式失败提供重试。都需明确状态。

不允许：悄悄改用别的ASR/模型、按住说话替代默认自动识别、播放时关麦伪装双工、每句固定回应、绕过dsh直接另写一套DeepSeek登录、以静音阈值当完整轮次判断、把角色提示词覆盖应用协议。
