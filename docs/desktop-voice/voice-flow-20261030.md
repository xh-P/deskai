# 语音边界与输出等待修订（2026-10-30）

用户反馈：外放播完后说“那你不就是外星人”，句中略有停顿，识别被拆碎且开头出现日文；外放期间插话“感觉还可以”，结果遗漏开头。用户明确保持中日英自动识别，选择约一秒内续说合并、优先保证完整性。

没有保存这两次原始录音，因此不能仅凭截图认定丢字发生在麦克风、AEC、前端 VAD 还是 ASR 内部。以下修订针对已查明的链路职责与可复现问题，不宣称真实外放验收通过。

## 输入区间的唯一所有者

旧链路在前端 600 ms 静音时结束音频，又在 SenseVoice provider 内按 500 ms 静音二次切分，每段分别自动识别语言。前端将文本拼起来，无法修正已经按过短上下文识错的语言或文字。旧起音缓冲只有 250 ms；provider 只有请求首段回填 300 ms，后续子段没有同样的回填。

现在由 `InputEndpoint` 管理候选音频的保留、重开和冻结，`InputController` 管理连续样本、识别版本和提交：

1. 600 ms 静音产生候选快照并启动 ASR。桌面使用用户选定的 1000 ms 确认窗口；明显未完句保留 1200 ms 窗口。这些时间按最后有效语音样本计算，ASR 与确认等待重叠。
2. 确认窗口内续说，恢复原 PCM 与中间所有样本，以同一 `utteranceId`、新的 `inputRevision` 重新识别完整音频。旧任务可以完成，但旧成功/失败结果都不能覆盖新版本。不取消并销毁热 ASR worker，不猜补文字，也不删除用户重复词。
3. 发布 `ready` 时冻结区间，避免正在提交的旧前缀与新音频混淆。发布后的新起音撤销旧资格；迟到的模型接纳回执只消费原前缀，不能重发已接纳内容。
4. 候选识别快照允许重叠，最终接纳的语义区间不重叠。20 秒硬上限只切音频，不能单独触发模型回答。缓存与待处理语义片段有上限；被替换但还在运行的旧 ASR 最多一项。
5. 起音环保留 800 ms，活动语音使用起音/释放滞回。renderer 为每帧传递连续采样位置；缺帧或错误格式明确暂停采集，并恢复尚未确认取消的输出候选，避免静默拼接缺失音频。

专用 dsh overlay 将 speech Remote 和 provider 的规范 WAV 上限统一为 **20 秒、640044 字节**；provider 静音切分和最大段阈值均为 **21 秒**，在合法应用区间内不会触发二次切分。保留 VAD 有无语音检测（阈值 0.5、最短语音 0.25 秒）、请求首段最多一秒起音回填、`auto` 和热 worker。21 秒是区间约束，不是新的句尾等待：worker 收到完整 WAV 后同步扫描并 `flush()`，不等待真实 21 秒。

这份 overlay 同时供 M0 探针使用，因此 M0 也受 20 秒上限约束；原 dsh Web profile 不变。整段 ASR 会计算内部停顿，计算量和噪声影响需要实测。800 ms 缓冲与一秒回填都有限，不能保证恢复任意弱起音；噪声门也不能保证保留所有极短回答。

## 输出与诊断

明确的中日文句末和英文问号/感叹号不再等待下一个文本增量或 EOF 才交给 TTS；英文句点仍保留缩写/小数判断。校验后的非末 PCM 块可先交给播放器，末块必须等待合成成功才能标记完成。原有取消身份、三秒前瞻、回执和交付账本继续生效。

GPT-SoVITS v2 的整句推理模式未改变。此次消除的是文本切句与音频运输阶段的额外等待，不等于实现了句内低延迟生成，也没有真实端到端首声指标。

“技术设置与诊断 → 刷新语音时序”可读取当前内存中的输入/输出事件，各最多 100 条。事件包括候选、重开、识别开始/完成/过期、可提交、模型开始/首正文、TTS 开始/首 PCM/完成以及播放器提交。统一使用主进程单调时钟；只记录身份、样本区间和时间，不记录对话正文、音频或凭据。`playback-enqueued` 是提交给播放器的时间，不是声音抵达耳朵的时间。
