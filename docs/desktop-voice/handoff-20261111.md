## 已发现的差距与拟定方案（待实施）
- Amadeus 同时保留原始麦克风、AEC 残差和实际播放参考；先做近端语音判断，再以声学相关性排除自回声，确认后打断，并移交预录音。
- 本地 WebRTC 采集目前主要把残差交给 VAD，缺少上述同步信号及确认链路。拟将采集、回声判定、插话确认分开，配置集中管理，并串通播放状态与取消/恢复。
- 上游参考参数：播放起始保护 350 ms、最小 RMS 0.012、VAD 阈值 0.55、确认 96 ms；这些是对照依据，不是已移植或已验证的本地参数。
- 上游 echo guard 使用分频段声学特征与近期播放参考比较，不是文本匹配。应直接核对源码后移植，避免只复制阈值。
- Chromium browser 模式取得的是浏览器处理后的音频，不能称作独立的原始麦克风信号。必须按实际信号能力设计。
- 既有 AEC 研究发现误抑制风险；不能用单元测试替代真实外放双讲验收，也不能宣称上游原始信号回退必然解决严重误抑制。
